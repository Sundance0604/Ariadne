# 马勒第四：本地视频接入实测

> 本文保留视频接入初版的验收记录。后续已新增自动候选谱面高亮与文献修订，当前状态见 [跟谱与分析实测](mahler4-score-sync.md)；不再以本文“尚无坐标”的旧状态描述最新版。

日期：2026-10-25。保留既有 Python + 原生 JavaScript 校验播放器；本次没有迁移 React，也没有修改马勒第七的 OMR 工作。

## 输入和离线处理

- 用户视频：1,168,228,684 字节，3,785.27 秒（63:05.27），1920×1080 H.264，约 29.97 fps，AAC 44.1 kHz 双声道。SHA-256 为 `eb9a3ad6e19d775de29cc53b224c1b2c5ede83c7c274a7e463be3fe52945a5fb`。
- PDF：127 页，扫描图像与 OCR 文字。查看原页图像后确认四个乐章首页为物理第 5、49、78、102 页；没有推断逐小节矩形，也没有均分页面。
- 四个辅助 MIDI：分别得到 355、382、322、185 个候选小节，原有速度、拍号、轨道、端口信息保留。合并参考总计 1,244 个候选小节、43,291 个音符区间，41,901 个有音高区间用于特征。
- FFmpeg 7.1 将原视频第一音轨提取为单声道、22,050 Hz、16-bit PCM WAV，缓存在 `.tools/video-audio/`，仅供分析，播放读取原 MP4。当前环境没有 ffprobe，轨道信息使用 FFmpeg 的实际诊断输出回退，记录在 `works/mahler-4/media-sync.json`。精细轨道时间轴的 ffprobe 复核仍待完成。
- Sync Toolbox 1.4.2，chroma + DLNCO，MrMsDTW，50 Hz 特征，另运行 chroma-only 对照。实测耗时约 257 秒。不是按时长或固定速度分配小节。
- 所有计算与媒体读取均在本机完成，没有上传。用户的视频文件名提供阿巴多 / 琉森 / 2009 年信息；独唱者、发行资料与完整音乐学分析尚未核验或编写。

## 候选结果及限制

结果与原始路径在 `works/mahler-4/alignment.json`、`alignment.path.npz`；原始解码音轨的结果另留 `alignment.raw.json`。正式播放映射使用原视频指纹，保留提取音轨的来源信息。

全曲候选时间单调，未出现倒退或折叠的小节间隔。chroma-only 对照有 1 处起点差异超过 2 秒，另有 1 处超过 30 秒的间隔。全部 1,244 个候选小节都没有人工验收；扫描谱坐标全部缺失，首尾和乐章连接处另有试听复核标记。两种特征的一致性不是校准过的准确率，也不能证明乐章间停顿或 MIDI 版本完全对应。

## 播放实现与实际验收

统一控制器复用现有小节选择、播放线及分析模块，以当前主媒体时间驱动。新增 MP4 模式、底部播放 / 进度 / 音量 / 变速 / A/B 循环、三种桌面布局、窄屏标签、全屏与浮窗入口。布局只改变样式，媒体节点持续保留。全屏与浮窗的可用性仍取决于浏览器；本次未逐浏览器验收。

实际在本地浏览器播放了用户原始 MP4：解码就绪，画面宽 1920，视频发声时隐藏音频保持暂停、静音。切换观演与专注时保留同一个媒体 URL、时间与播放状态；专注隐藏画面后继续播放。跳转候选小节、0.8 倍速以及 A/B 循环回跳均已操作验证。选择第四乐章后同时跳到约 47:59.73 与物理第 102 页。

390×844 窄屏测试中，视频标签可见，内容没有横向溢出，播放器固定在视窗底部。随后恢复桌面尺寸。真实切换回拉威尔后，MP3 可播放且视频暂停并清除了来源。

服务端使用分段读取，测试了原始 1.16 GB MP4 的文件开头、约 800 MB 处及末尾后缀请求，返回字节与原文件一致。无效范围返回 416；没有视频的旧曲目返回 404。视频大小与修改时间触发 SHA-256 缓存核验，替换媒体时不继续套用旧映射。

另用本地 FFmpeg 生成了 1 秒无音轨 MP4：准备工具返回 `hasAudio=false`、`analysisAudio=null`、`matchStatus=manual_only`，没有报告自动匹配成功。

## 双媒体支持的边界

控制器与本地保存接口已支持经人工核验的分段递增音画锚点、映射区间限制、单一发声音源、受限漂移校正和校正历史。保存需要匹配当前曲目及两个媒体指纹，填写核验依据并确认同一演出。区间以外暂停视频；超过 2 秒偏移时暂停静音视频并提示检查，不反复强制跳转。不同或未经确认的演出禁止启用双媒体同步。导出项目仅包含 JSON 数据，不打包媒体。

**用户本次没有提供独立 MP3。** 这一部分目前只有控制器与接口测试，未对用户真实的 MP3 + MP4 组合验收；自动音频间匹配、固定偏移检测、剪辑检测与音频间 DTW 尚未实现。不能宣称增量规范中这些验收项已经完成。

## 测试与复现

- Python 完整回归：57 项，55 项通过，2 项原有 M4A 悬置实验跳过。证据：`reports/video-regression-tests.log`。
- JavaScript 控制器：6 项通过，覆盖分段 / 反向映射、视频时钟、纯音频、切源单一发声、不同演出拒绝、漂移与有效区间。证据：`reports/video-controller-tests.log`。测试用媒体替身，不能替代真实双媒体演出验收。
- 无音轨实际文件检查通过；用户 MP4 的浏览器操作记录见上文。

播放无需重算：`python start.py`，然后选择“马勒 · 第四交响曲（视频）”。本轮预览端口为 8766；默认启动端口为 8765。

重新计算：安装 `requirements-processing.txt`、`requirements-media.txt`，运行 `python scripts/build_mahler4_video.py --align`。重新计算沿用视频原文件指纹，人工确认结果受覆盖保护。已有人工锚点可使用独立输出路径：

```powershell
python scripts/align_recording.py --audio 'resource/mahler No.4/【交响乐】阿巴多 琉森节日管弦乐团 马勒第四交响曲（2009）.mp4' --midi works/mahler-4/auxiliary.mid --anchors works/mahler-4/review-anchors.json --output works/mahler-4/alignment.corrected.json
```

纠正版不会自动替换当前结果。全谱 PDF → OMR → 不依赖用户 MIDI 的对齐，以及扫描谱逐小节坐标，是后续尚待完成的工作。
