# classicMusic — 视频功能增量规范（VIDEO_EXTENSION.md）

> 交给 Codex 的增量开发说明。保留既有 PDF → OMR → 离线音频—乐谱对齐、独立音乐学分析、可选 MIDI 工作流。**MP4 可选，仅用其中音轨对齐，不分析视频画面。**

## 一、目标和三种播放模式

| 输入 | 主时钟 | 功能 |
|---|---|---|
| MP3 + PDF | MP3 | 原有纯音频导聆，保持兼容 |
| MP4 + PDF | MP4 | 提取 MP4 音轨进行离线乐谱对齐，视频的 `currentTime` 驱动总谱和注释 |
| MP3 + MP4 + PDF | 优先 MP3 | 使用高质量 MP3 发声，MP4 静音，借助两个音轨之间的时间映射同步画面 |

MP3 与 MP4 只有在**同一演出或同一录音版本**时，才能预期较好的音画精确同步。不同现场演奏可能有速度、停顿和细节差异，不能仅凭作品相同就宣称严格同步。若发现不同版本，提示用户切换为以 MP4 音轨为主并单独对齐总谱，或者采用明确标注为近似的乐谱小节同步。

## 二、离线对齐工作流

```text
PDF 总谱 ── OMR ── 小节 ID / 原谱坐标
                      │
MP3 ── 音频→总谱对齐 ──→ alignment.json
                      │
MP4 ── 提取音轨 ─┬──→ 仅 MP4 时独立音频→总谱对齐
                 └──→ 同时有 MP3 时，MP4 音轨↔MP3 音轨匹配
                                ↓
                         media-sync.json
                                ↓
                      React 统一播放控制器
                                ↓
             PDF 高亮 + 文字解读 + 演奏视频
```

用 `ffprobe` 检查 MP4 的时长、轨道、编码信息与时间轴；用 FFmpeg 提取音轨。下面是仅在存在音轨时适用的示例命令：

```bash
ffmpeg -i input.mp4 -map 0:a:0 -vn -ac 1 -ar 22050 -c:a pcm_s16le extracted.wav
```

音轨提取只服务于离线分析；实际播放仍读取原始 MP4。不做视频帧识别，不依赖计算机视觉模型。

优先先检测固定起始偏移（例如片头掌声、留白），再判断是否发生漂移。只有确有剪辑、时间伸缩或局部偏差时才使用分段锚点、音频特征和必要的 DTW。出现无法可靠匹配的区间必须报警并支持人工锚点校正。MP4 没有音轨则不可能自动完成音频匹配，只能使用手动锚点。

## 三、数据结构

延续项目中既有的 `measure_id`、`alignment.json`、`annotations.json`。每份录音保留独立的乐谱对齐映射，不共享未经验证的绝对时间戳。

建议新增 `media-sync.json`，记录：
- `masterMediaId`、`videoMediaId`、`masterClock`；
- MP3/MP4 文件指纹、时长和版本标记；
- `method`、`matchStatus`、`qualityWarnings`；
- 单调递增的 `anchors[]`，每个锚点为 `{masterTime,videoTime,reviewStatus}`；
- 人工校正记录、算法参数与有效区间。

这里的本质是三个映射：`t_mp3 → measure_id`、`t_video → measure_id`、`t_mp3 ↔ t_video`；不一定每个项目都同时拥有全部映射。音乐分析注释仍然只与小节/结构事件关联，不直接写死在视频时间戳上。

## 四、统一播放器

创建或复用唯一 `PlaybackController`，管理播放、暂停、拖动、速度、循环、主音源选择及切换。PDF、视频、分析面板都消费同一个位置状态，避免各自单独计时。

MP4 模式使用视频 `currentTime` 驱动所有面板；MP3 优先模式使用音频 `currentTime` 驱动 PDF/注释，并通过分段映射计算视频时间，视频始终静音。任意时刻只能有**一路可听音源**。小幅漂移通过受控校正处理，明显偏移时提示检查，不要无限频繁 seek。跳转位置、改变播放速度及切换布局必须同步全部视图。

浏览器的 `requestVideoFrameCallback()` 可辅助读取帧对应的时间信息，但小节高亮无需每帧重渲染。处理自动播放限制、MP4 编码兼容性、失效本地文件、对象 URL 清理和缓冲等待。

## 五、默认 React 桌面界面

```text
┌───────────────────────────────────────────────────────────┐
│ 作品 / 录音  [研读] [观演] [专注]           设置 / 全屏     │
├────────────────────────────────┬──────────────────────────┤
│                                │ 音乐分析（当前段落）       │
│ 原始 PDF 总谱（约 55% 宽）      │ 事实 / 解释 / 聆听提示    │
│ 当前小节高亮                   │ 文献来源 / 复核状态        │
│ 可滚动、缩放、翻页              ├──────────────────────────┤
│ 可关闭自动跟随                 │ 视频（自适应 16:9）       │
│                                │ 放大 / 隐藏 / 浮动        │
├────────────────────────────────┴──────────────────────────┤
│ 统一播放器：播放 / 进度 / 小节跳转 / 音量 / 速度 / 循环    │
└───────────────────────────────────────────────────────────┘
```

默认“研读模式”：左 PDF，右侧上分析、下视频，窗格可拖动调整大小。分析按**乐句或音乐事件**显示，不强迫每小节更换整段文字。PDF 跟随可暂停，以方便对照阅读。

“观演模式”：视频占主区域，乐谱缩至侧栏，解读可折叠。“专注模式”：大幅乐谱 + 解读，视频隐藏或浮动小窗。切换模式不重载媒体、不丢失时间进度。

在手机/窄屏中使用“乐谱 / 解读 / 视频”标签切换，底部播放器固定。复杂总谱不应为了整页适屏而缩小到无法阅读；允许放大、平移和当前系统聚焦。

## 六、测试与验收

| 真实测试 | 验收点 |
|---|---|
| 无 MP4 | 原纯音频功能完全正常 |
| 仅 MP4 + PDF | 自动提取音轨，离线对齐，视频驱动小节高亮和注释 |
| 同演出 MP3 + MP4 | MP3 发声、MP4 静音，片头偏移后正确同步 |
| MP4 有剪辑/漂移 | 标注疑点，支持分段锚点和人工修正 |
| 不同演出 MP3 + MP4 | 禁止伪装成已精确同步，给出回退方案 |
| MP4 无音轨 | 提示手动锚点，不报假成功 |
| 点击 PDF 小节/文字/时间轴 | 音频、视频、乐谱、分析统一跳转 |
| 调速、循环、反复暂停、频繁 seek | 不重复发声、不死循环、不明显乱跳 |
| 窗口缩放、三模式切换 | 布局正常，媒体状态不丢失 |
| 公共项目导出 | 不默认打包或上传未经许可的 MP4/MP3 |

## 七、给 Codex 的执行指令

请先读取仓库当前 `WORKFLOW.md`、前端组件、媒体播放器、`alignment.json` 与 `annotations.json`。在**不重写现有播放器**的条件下实现可选视频功能。先完成静态 MP4 加载、统一时钟、默认双栏布局；再增加 MP4 音轨提取与离线总谱对齐；最后实现 MP3 主音源下的静音视频同步、多锚点校正与响应式模式切换。所有新功能应有可验证的真实文件测试，未通过的不标为完成。

音频、视频和 PDF 默认只作本地处理；未经许可不得上传或公开商业录音、演奏视频与乐谱。文献和乐谱分析模块仍保持独立。
