## 1. 研究范式：两条阅读路径、三个认识层次

### 1.1 两条阅读路径（用户可见）

**A. Structural Analysis / 谱面技术分析**

依附于总谱、当前位置与播放进度，包含：

- `harmony`：音集合、和声类型、调性中心、和声功能、和声节奏；
- `counterpoint`：声部进入、模仿、对位关系、悬留与解决、织体；
- `form`：乐章／段落／乐句的层级位置及结构功能；
- `orchestration`：当前声部／乐器、音区、配器和音色组织；
- `motif`（架构预留，可选显示）：动机、主题及其变化。

这些维度**独立更新**：和声可能一拍或一小节变化，曲式可能许多页面不变，配器则具有另一组变化边界。不要以当前 PDF 页码作为所有技术事件唯一的更新频率。

**B. Hermeneutic Analysis / 音乐诠释与研究**

阅读对象为文章、论证、评论或研究专题，包括：

- 历史背景、作品委约、创作语境与版本问题；
- 曲式、和声、对位、音色在更长时间跨度中的意义；
- 作品接受、演奏比较、作曲家文字、学术争论；
- 审美与哲学解释，包括可以存在竞争性观点的情形。

一篇文章可关联**多段非连续**谱面区间；它不能被简化为当前页的一段 Markdown，也不能因每次播放位置跨过小节线而重置用户的阅读位置。

### 1.2 三个认识层次（数据中必须区分）

| 层次 | 意义 | 举例 | 验证原则 |
|---|---|---|---|
| `score_observation` | 乐谱中直接可观察的事实 | 某个声部出现特定音、乐器进入、速度文字 | 原版／目标 PDF 和声部核对 |
| `theoretical_analysis` | 基于理论框架的推断 | 四度叠置、属功能、曲式边界、动机变形 | 注明采用的框架、依据与异议 |
| `hermeneutic_interpretation` | 历史、审美、哲学的诠释性命题 | 调性发展与戏剧性含义、社会历史解读 | 对应文献／证据／明确解释者 |

UI 可以只有“技术／诠释”两组，但**知识库绝不能把「理论推断」自动提升成「事实」**。对现代和声尤其不要强制将每个瞬间都写成传统罗马数字；必要时允许「非功能性和声／持续音／音集合／理论争议」。

**理论参照**：汉斯立克（形式主义）、纳蒂埃及 Molino 的音乐符号学（内部结构／创作／接受的区分）、阿多诺（形式与历史意义的互相关联）。这是方法论来源，不要求对每个乐段强行套哲学观点。研究记录中区分“论文作者的解释”和“本项目已经核定的事实”。

## 2. 新的数据模型：先让信息可追溯，再让它动起来

本轮请在拉威尔既有数据目录下新增适量结构化文件。例如：

```text
analysis/
  annotations.json                 # 保留现有的 15 段页码导聆，不破坏
  structural-events.json           # 新增：按维度独立定位的技术事件
  hermeneutic-essays.json          # 新增：跨区间研究专题／文章
  sources.json                     # 可选：统一学术来源登记（勿重复造轮子）
docs/
  ARIADNE_RESEARCH_PARADIGM.md     # 研究范式、定位模型、认识论状态
  RAVEL_PILOT_REPORT.md            # 本次实测、证据与未完成项目
```

文件名可根据现有架构做小幅调整，但需记录最终接口。新数据不应依赖硬编码页面组件才能解析。

### 2.1 定位模型必须区分三个坐标系

1. **作品／乐谱坐标**：作品、乐章、乐谱版本、物理 PDF 页、系统、原谱小节、拍位、可选声部；这是分析的**首要锚点**。
2. **录音时间**：由当前录音对应的 `alignment` 和经过人工修正的 `score region` 投影得出。不同录音拥有不同时间映射。
3. **视频时间**：沿用现有媒体主时钟与音画锚点。音乐分析不直接永久绑定某个 MP4 时间。

优先使用稳定、可区分版次的 `edition_id`、PDF 指纹和谱面定位 ID；不足以精确定位时允许 `page_range`、`score_segment_candidate`、`unlocated`，不要虚构小节号。字段允许空值，**未知必须与不存在区别开来**。

**技术事件可不止一个小节**，也允许一小节存在多个事件。跨小节的悬留与解决、快速和声变化必须能够表示；未来允许精确到拍位／音符 ID，但本次不必全部实现。

### 2.2 技术事件示例（仅作为 schema 说明，禁止原样标为已验证）

```json
{
  "schema_version": "1.0.0",
  "work_id": "ravel-left-hand-concerto",
  "edition": {
    "edition_id": "ravel-reengraving-100p",
    "pdf_sha256": "READ_FROM_CURRENT_MEASURE_MAP"
  },
  "events": [
    {
      "id": "ravel-opening-harmony-quartal",
      "dimension": "harmony",
      "claim_level": "theoretical_analysis",
      "short_label": "四度叠置音响：E–A–D–G",
      "detail_markdown": "按照相关论文的分析，开头的音响可从四度叠置关系理解。必须进一步核对当前谱本。",
      "score_spans": [
        {
          "pdf_page_start": 1,
          "pdf_page_end": 3,
          "precision": "page_range",
          "region_ids": []
        }
      ],
      "sources": [
        {
          "source_id": "leong-korevaar-2005",
          "locator": "relevant sections",
          "claim_attribution": "authors"
        }
      ],
      "verification": {
        "score": "pending",
        "literature": "relevant_sections_checked",
        "location": "page_range",
        "timing": "candidate_alignment"
      }
    }
  ]
}
```

注意：上面 `pdf_page_start`、`pdf_page_end` 只是演示可用的较粗定位，绝不意味着这些页的每个小节都持续出现同一个和弦。正式条目必须收紧到实际可证的区间，否则只显示为“段落背景信息”，**不得充当精确实时和弦读数**。

事件应支持：

- `dimension`、`claim_level`、简短 HUD 文本、详解 Markdown；
- **一个或多个** `score_spans`，每段有独立定位精度；
- `sources`（页面、声部、原谱、论文 DOI／链接与具体章节；阅读状态）；
- 独立的 `verification.score / literature / location / timing`；
- 可选 `analysis_framework`、`alternatives`、`reviewer`、`reviewed_at`；
- 允许同一时段有多条结构观点，不覆盖或静默删除争议；
- 版本/文件指纹不匹配时拒绝将内容伪装成适用于当前 PDF。

**不要使用虚假的浮点置信度**。MVP 采用明确的 `verified / pending / disputed / not_applicable` 等状态即可；区分机器候选和人工确认。

### 2.3 诠释文章示例（允许非连续区间）

```json
{
  "schema_version": "1.0.0",
  "work_id": "ravel-left-hand-concerto",
  "essays": [
    {
      "id": "ravel-tonal-emergence",
      "title": "调性的逐步确立：引子、华彩与乐队重入",
      "claim_level": "hermeneutic_interpretation",
      "reading_mode": "persistent",
      "score_spans": [
        {"pdf_page_start": 1, "pdf_page_end": 9, "precision": "page_range"},
        {"pdf_page_start": 10, "pdf_page_end": 14, "precision": "page_range"},
        {"pdf_page_start": 15, "pdf_page_end": 23, "precision": "page_range"}
      ],
      "related_event_ids": ["ravel-opening-harmony-quartal"],
      "source_ids": ["leong-korevaar-2005"],

```

这组页码取自当前仓库的拉威尔导聆分段，仅作为初始定位假设，**不能代替详细的小节校勘**。文章正文可作为独立 Markdown 文件，也可按现有安全渲染方法储存；优先复用 Mistune，安全转义 HTML、校验 URL，不接受未清洗的脚本。

一篇文章可以引用多个 `related_event_ids`；点击某段论证可导航到谱页／区域，而不是要求文章本身与播放器时间实时一一对应。

## 3. 实现结构仪表 Structural HUD

### 3.1 视觉位置和行为

延续现有三栏格局。**技术仪表放在中间 PDF 阅读区，而不是右侧长文中**。

建议：

- PDF **左上信息区**：`和声 Harmony`、`对位 Counterpoint`；
- PDF **右上信息区**：`曲式 Form`、`配器 Orchestration`；
- `动机 Motif` 可作为折叠扩展项，数据层先支持；
- 卡片保持简洁：第一行仅当前标签、第二行可选简短摘要、细小文字标明定位/核查程度；
- 点击标签显示相关详细分析和谱面来源（可复用右栏或提供详情抽屉）；
- 未确认内容明确展示“待复核”或“仅定位到谱页”；确实没有数据时显示“暂无可靠分析”，不要虚构；
- 在 `study`、`watch`、`focus` 三种模式以及桌面、窄屏、移动端中都要可用。

**推荐把 HUD 固定到“乐谱阅读容器的顶部”，不要直接烧录或绝对定位到 PDF 图片坐标里。** 可在 `.score-scroll` 上方加一条属于谱面区域的紧凑仪表栏，视觉上接近左上/右上贴边，既随用户看谱保持可见，又不遮挡第一行乐谱。全屏或观演模式可使用可折叠的小浮层，但不应挡住播放线与谱面定位。

尽量复用原有色彩、字体、间距，不做全面视觉重构。避免信息密度过大、卡片闪烁或每小节导致整页跳动。

### 3.2 更新机制：必须独立于诠释文章

现有 `review/app.mjs` 的 `updatePlayhead()` 和 `syncPlaybackPosition()` 已使用统一媒体时间与谱面区域；可把新的 `structuralHUD.update(context)` 挂接在同一个播放上下文中。

重要约束：

- **实时 = 随播放即时显示预计算／已审核的分析，不是每一帧发 LLM 请求。**
- 在曲目载入时装载、验证和索引技术事件；播放中仅查询事件索引。
- 各维度按自己的起止锚点或定位精度独立更新：某个维度不变化时，不必重建 DOM。
- 仍使用当前实际演奏作为主时钟，与现有音视频映射共用时间线。
- 变速、暂停、seek、A/B 循环、换曲、用户手动翻页、自动跟谱关闭都必须正确响应。
- **正在播放的位置**与**用户手动浏览的页**不是同一个状态。HUD 默认依附播放位置；当二者不同，适当标识“播放位置 / 浏览页”，不得把手动翻页误认作音频已跳转。
- 候选时间、页码和原谱小节不一致时，以保守、可解释的回退规则处理。绝不把 PDF 候选编号 `≈` 改写成已确认的小节真值。
- 数据缺口期间不要继承上一个和弦的标签，仿佛它仍然有效。

建议新增原生模块 `review/structural-hud.mjs`，负责索引、状态与渲染，必要时把纯函数分为便于 Node 单测的模块。旧代码尽量只增加加载和更新接线。

### 3.3 精度与冲突处理

按照数据所能支持的精度显示：

- 已核对原谱小节或拍位：允许呈现为准确定位的瞬时／区间技术标签；
- 只有 `score_segment`：呈现为区域级提示，不假装逐拍有效；
- 只有 `page_range`：只能显示“本页／本段相关的背景分析”，不能把跨 9 页的观点写成每一刻的实时和声；
- 不存在可靠定位：不自动随播放激活，只放在可浏览的研究资料中。

事件冲突时允许并列展示“不同理论解释”，或显示“存在争议”并进入详情，不要简单选取 AI 最新生成的一个答案作为真值。以人工校核、定位精度和明确来源提高可信度，但不因状态好就抹去学术分歧。

## 4. 实现诠释文章 Hermeneutic Essays

在右侧 `.analysis-content` 中保留原有 `当前导聆 / 曲目信息 / 参考文献`，新增 `诠释研究` 标签。现有 `review/analysis.mjs` 可扩展或增加独立模块 `review/hermeneutics.mjs`，但不要破坏已有导聆。

交互要求：

1. 文章目录可选不同研究专题，至少支持一篇长论证；
2. 默认阅读模式**不强制随播放重新打开文章，也不自动把阅读栏滚动到顶部**；
3. 增加明显但克制的“自动跟随相关诠释”开关。关闭时锁定当前文章；开启时仅在相关专题真的切换时更新文章，而非每次时间更新都重绘；
4. 一个专题可关联多个不连续 `score_spans`，UI 列出“相关乐段”，点击可跳转到 PDF 和对应录音候选时间；
5. 如果只有页级定位而没有可信的录音起点，只打开该 PDF 页面并标注“音频位置待核查”，不得凭空精确 seek；
6. 文章可独立滚动、逐条查看引用来源／阅读核查状态，不因分页、播放线移动、切换其他标签而被销毁；
7. 相反方向也要成立：点击 HUD 的某个技术事件，可以跳到它的详细解释／关联文章；
8. 确保当前作品切换后，不会残留上一篇作品的 HUD 或诠释文章。

要解决现有 `analysis.mjs` 某些播放变更会重设右栏滚动位置的逻辑：这种行为可以保留在现有“短导聆”中，但不能影响新的“长文章”阅读组件。

可以**复用马勒第四已有的同页分段导聆逻辑作为定位参考**，但新诠释层必须支持“多段、非连续、跨页”的关系，不应只是 `score-guide.json` 的另一个单一连续时间范围。

## 5. 后端集成与兼容

建议增加一个只读接口，例如：

```text
GET /api/research?track=ravel-left-hand
```

响应包含（或按需要拆分）当前作品的结构事件、诠释文章、参考资料和版本校验信息。复用现有 `/api/library` 的曲目白名单与 `track_context`，拒绝路径穿越、错误曲目、错误文件指纹。若研究文件不存在，返回合法的空结果而不是破坏播放。

在 `scripts/serve_review.py` 提供最小 JSON API，读取数据由独立 Python loader 验证。给新 `.mjs` 模块增加静态资源路由，沿用现有 `start.py` 的启动路径。

建议把“谱面区间 → 录音时间”的投影放在播放器运行／数据加载阶段，使用已有 `alignment`、`measure-map`、校正锚点；**不要把某份录音的秒数当作分析事实永久写进作品级研究内容**。数据确有特定演奏观察时单独绑定 `recording_id` 和音频指纹。

保留原有 `analysis/annotations.json` 的 15 个拉威尔短导聆段落；新研究数据与旧数据并存。马勒第四、《云雀高飞》暂时没有新数据也应无异常运行，可显示 HUD 空状态或隐藏新增标签，而非抛出错误。

## 6. 拉威尔《左手钢琴协奏曲》试验范围

本轮以一个**真的可点击、可跳转、可追溯、能随音乐更新的实验样板**为交付目标，严禁用看似完整但未经验证的全曲自动标注冒充研究成果。

### 6.1 重点谱面

| 目标谱页（当前100页重排谱） | 分析目标 | 检验问题 |
|---|---|---|
| 1–3 | 引子：低音弦乐、低音巴松、四度叠置相关论点 | 乐谱观察、理论解释、声部配器能否分离 |
| 10–14 | 第一次钢琴华彩 | 单手的多声部织体；缺少稳定小节线时如何定位 |
| 15–23 | 乐队重新参与 | 与引子／华彩共同构成长跨度的调性解释 |
| 33 起 | Allegro 快速段 | HUD 不同维度以不同频率更新 |
| 91–95 | 末段华彩及乐队重入 | 主题回归及跨页意义阐释 |

这些页码源自本仓库当前导聆，**不是已经校核的准确小节边界**。如果校验时发现与谱面冲突，应修正新研究记录，不随意修改旧导聆或已有媒体坐标。

### 6.2 第一篇跨页面研究文章

标题建议：**《调性的逐步确立：从 E，经 A，至 D》**。

现有资料中已经引用 Leong & Korevaar（2005）关于本曲引子、开头华彩与乐队重入的结构性论述。**这应以“学者提出的分析框架”形式呈现，不作为所有小节的客观和弦读数，也不直接声称拉威尔自述了该创作意图。**

第一篇文章必须能够：

- 联结引子、华彩、乐队重入的非连续／多段谱面证据；
- 从文章中的具体乐段跳回 PDF，只有在定位足够可靠时才跳音频；
- 播放音乐时，HUD 继续更新，而长文章与其滚动位置保持不动；
- 逐条标注哪一部分是谱面观察、哪一部分是论文观点、哪一部分仍待核查。

学术参考优先使用当前仓库原文已经收录、阅读状态已有记录的资料，至少核对：

- Leong & Korevaar（2005）：https://mtosmt.org/issues/mto.05.11.3/mto.05.11.3.leong_korevaar.html
- Beavers（2021）：https://mtosmt.org/issues/mto.21.27.1/mto.21.27.1.beavers.html

不得把只读过摘要的文献描述为已核查全文。若无法访问正文，保留真实的访问限制、不要补造论点。

### 6.3 数据填充边界

为演示功能至少录入：

- 两个或以上**确有不同有效区间**的技术事件，让 HUD 可以观测到独立切换（如果仅能核查到页级事实，则诚实标为页级背景提示）；
- 一篇有至少三段关联谱面范围的诠释研究文章；
- 每条演示内容含来源、定位精度与核查状态。

**不要为了让四个 HUD 格子都显得满当而编造四维全覆盖。** 只有被真实谱面或已读文献支持的内容才能写成有内容的标签。其余维度采用明确空状态；若需要模拟更细的逐小节切换行为，可只放在**测试 fixture**，不能混入生产分析数据。
