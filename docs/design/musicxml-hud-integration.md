## 0. 本轮目标：统一呈现，不重新发明引擎

用户现在遇到的问题不是缺少第三套和声识别器，而是**同一份音乐知识以几套不同时间尺度、认识层次、证据来源，重复出现在谱面上方**。

当前至少存在以下并行机制：

1. `review/musicxml-live.mjs`：按估计的 XML 谱面时点展示**当前记谱音响的并列读法**与**活跃分部**。
2. `review/structural-hud.mjs`：分别展示**和声、曲式、对位、配器**的逐谱研究、MusicXML 小节研究及可选旧算法候选。
3. `review/musicxml-evidence.mjs`：独立选择全部 535 个 MusicXML 小节，展开和声、配器、声部与逐音底稿。
4. `review/hermeneutics.mjs`：右侧保留跨页、跨段的独立诠释文章。

现在 `review/index.html` 将 `#musicxml-live`、`#hud-toggle/#structural-hud` 与 `#musicxml-reader` 纵向堆在 PDF 之前，既重复，又压缩了乐谱可视面积。

**本轮最终目标：一个紧凑的四维 Structural HUD，内部区分实时记谱事实、局部理论解释与跨段结构判断；一个可逐级展开的证据体系；一个始终占据主要视觉空间的 PDF。**

不要删除任何已有研究记录，也不要把细粒度数据简化成缺乏来源的一句话。

## 2. 最重要的音乐学约束：四个层次不能混成一个标签

### 层次 A：记谱事实（Notated facts）

- 当前 MusicXML 标明仍处于记谱时值内的音符：音名、八度、音符 ID、起止、声部、实际记谱低音。
- 当前活跃的 XML 分部：乐器、音域、奏法、进入与退出、有效音符 ID。
- 这些是**记谱状态**，不是录音声学余响；踏板、震音、打击乐不得按没有根据的规则补成真实演奏事件。
- 分部数量不等于不同乐器种类、演奏员数量或独立旋律条数。

### 层次 B：局部音乐理论分析（Local theoretical analysis）

- 和弦/音集类型、层内根音、实际全体最低音、所选和声层最低音、转位、非和弦音或分层归约的推断。
- 织体/对位职责：持续层、旋律、加倍、对比层、独立副旋律等；仅由音域或时值启发的结论必须明确标为**候选**。
- 一项理论归约必须列出**纳入的源音符 ID**与**另列而没有纳入该归约的源音符 ID**，并说明为何分层。
- 局部调性候选与罗马数字只能作为条件性结果，不能将 Krumhansl–Schmuckler 相关系数理解为概率或将罗马级数直接等同于功能。

### 层次 C：跨时间的结构分析（Contextual structure）

- 背景和声/持续低音区间、和声节奏、跨和弦声部进行、配器交接、主题及动机发展、乐句与曲式功能。
- **背景和声不等于某个瞬时音集；没有充分核查时就写“背景和声待分析”。**
- 允许持续数拍或多小节，也允许一小节含多个不同的结构事件。
- 文献给出的调性与曲式大框架可以作为有来源的学术观点，但不能自动转写为当前音符的实时和弦标签。

### 层次 D：诠释学研究（Hermeneutic essays）

- 跨越不连续谱段的研究文章，允许不同学者观点并存。
- 继续保持当前 `#essay-body` 的阅读位置、展开状态和独立滚动；不能因 HUD 更新、播放跳转或证据查询而替换文章 DOM。

**工程上可保留 A/B/C 的多个数据表，但交互上只呈现一组和声、配器、对位、曲式入口。**

## 3. 界面重构：一个紧凑的四维技术仪表

### 3.1 常态视图

在 PDF 正上方保留一条紧凑 HUD（推荐两列或两行响应式布局），默认只显示每个维度最有价值的摘要：

| 维度 | 默认摘要 | 点击后展开 |
| --- | --- | --- |
| **Harmony · 和声** | **背景和声**（如有可信时间范围）＋**当前记谱音响**（和弦或音集/开放五度） | 条件性罗马数字、多层并列读法、音符依据、转位、和声归约理由、其他解释 |
| **Orchestration · 配器与织体** | 当前活跃分部数量与主要乐器；经核查的织体职责单独一句 | 每个分部的实际音符、音域、进入/退出、加倍、职责候选、跨段交接 |
| **Counterpoint · 对位** | 当前可定位的声部关系；无可信关系时“待分析” | 声部音程、节奏差异、独立性、仿效证据及来源 |
| **Form · 曲式** | 当前段落/结构层级及其定位精度 | 主题/动机、乐句功能、终止/返回假设及证据链 |

- **绝不能再把 `musicxml-live` 与 `structural-hud` 作为两套上下堆叠的“和声／配器”面板。** 仍可复用各自的函数、状态、数据及样式，但最终屏幕上每个维度只出现**一组入口**。
- 常态 HUD 控制高度，**不要让技术卡片比总谱更占屏幕**。实测普通桌面视口时，HUD 收起状态尽量压缩到约 100–160 CSS 像素内；这是体验目标而不是要求截断重要文本。长证据默认折叠。
- 技术详情优先在现有右侧栏增加一个**“技术证据”阅读面板**或等效的独立抽屉；若复用 `#hud-detail`，须确保详情展开不会长时间挤压 PDF，且用户可一键返回谱面。
- 保留 `#musicxml-reader` 的535小节独立研究能力，但默认折叠；可以作为同一技术证据面板的“完整小节数据”入口，**不要删除，也不要让选择小节自动 seek**。
- 桌面版保留大幅 PDF；移动端允许折叠四维摘要或切换“谱面/证据”，不能因为卡片堆叠而无法看谱。
- 优先改当前原生 JS + Python，**不得重写为 React**。

### 3.2 只展示一次，但要能层层展开

用户在第58小节看到 `G♭1、G♭2、D♭4、G♭4` 时，应能得到：

- **当前记谱音响**：G♭ 与 D♭ 两个音级、开放五度、多八度加倍；这不等于已判定功能和弦。
- **背景和声**：没有经过时间归约就标记为“待分析”，不可默认沿用前一个瞬时和弦。
- **配器**：钢琴独奏（若当前确实如此）；具体旋律/低音/分解声部须参考声部证据，不能由“只有1个分部”推出“只有1条音乐声部”。
- 点击摘要，进入本小节/本事件的全部源音符、时值、层次归约与已有研究文章链接。

其他小节如 m.11 的“上层和弦 + E1 持续低音”、m.64 的“E大三和弦上层 + A 持续层 + 随后 D 低音”，应**并列显示不同分析对象**，不迫使系统判定一个唯一和弦。

## 4. 数据与组件架构：统一 View Model，而非抹平数据来源

### 4.1 在 `review/research.mjs` 一处协调

建议新增一个轻量、可单测的研究视图模型适配器，例如 `review/score-analysis-model.mjs`（名称可与仓库命名规范一致）：

```js
// 参考形状：可以据现有 JSON 适配，不强求照抄字段。
{
  position: {
    source: 'estimated_playback', // 或 independent_xml_browse
    referenceSeconds: null,
    xmlQuarter: null,
    measureId: null,
    pdfPage: null,
    timePrecision: 'candidate_projection'
  },
  harmony: {
    surface: { windowId: null, noteIds: [], label: null, activeSpelledPitches: [] },
    contextual: { eventId: null, label: null, scope: null, status: 'unreviewed' },
    alternatives: [], // 每条包含 includedNoteIds/excludedNoteIds、层内根音/低音/全体低音
    linkedEvidence: []
  },
  orchestration: {
    activeParts: [], // 记谱时点真实活跃的原XML分部，非整小节并集
    observedRoles: [], // 确认的职责与规则候选分开
    transitions: [], // 进入、退出、交接的区间事件
    linkedEvidence: []
  },
  counterpoint: { localRelations: [], contextualEvents: [] },
  form: { activeHierarchy: [], localEvidence: [] }
}
```

- 一次加载保留 `/api/research`、`/api/musicxml-live` 的既有指纹检查、曲目隔离和缓存机制；**不要无必要复制 6,801 帧×乐器数据到多个独立前端状态**。
- 背景研究来自现有 `score_study`、原 `structural-events`、必要时已核查论文；XML 的 `musicxml_analysis` 逐小节事件作为**原始证据/小节索引**，不在简洁 HUD 里再次渲染四个同名按钮。
- 旧 `engine_candidate` 仅在用户勾选辅助候选时展现，并且标出 PDF/MIDI 候选身份；不覆盖 XML 主数据。
- **不改动、不删除 `analysis/engine/` 的冻结历史快照。**
- 为需要证据的内容只保存 ID 与 URL 引用；展开时复用 `/api/musicxml-evidence`、`/api/structure-evidence` 按需获取，避免初始页面加载整份巨大的音符 JSON。

### 4.2 不采用简单来源优先级覆盖

不写 `score_study > xml > engine` 然后选一个赢家。它们针对的**问题不同**：

- MusicXML：音符、时值、活跃分部等可计算事实（仍依赖转录质量）。
- 逐谱研究：指定窗口内的理论归约与人工可核查的证据（代理逐谱检查不等于用户签核）。
- 原研究事件：有定位精度约束的宏观/局部音乐学解释。
- 旧算法引擎：辅助候选与对照数据。

对相同主张若存在冲突，列出两项解释、适用范围和来源，而不是默默覆盖。若同一条信息已出现在多处，只在 UI 显示一条摘要，展开证据时列出关联条目。

### 4.3 四种不同更新周期

- `surface_harmony`：随 MusicXML 和声窗口变动。
- `live_orchestration`：随实际活跃分部与奏法/音区变动。
- `contextual_harmony`、`texture/counterpoint`：随有证据的结构区域变动。
- `form`：随层级/段落界限变动，不随着每颗音刷新。

仅在各自的稳定事件 ID 或内容签名变化时更新相应 DOM；保持播放动画帧中的计算轻量，避免破坏已有 PDF 播放线刷新速度。

播放位置和手动浏览位置必须分离。默认 HUD 反映**当前播放位置**；独立 MusicXML 阅读器可以查看任意小节，但不得更改当前录音位置或把浏览小节假装成正在播放的和声。若提供显式的“跟随浏览位置”选项，需有清晰状态标签。

继续采用前闭后开 `[start, end)`；沿用已有 MIDI 速度事件→参考秒→XML 四分音符映射，**只作为时间投影**。不得将尚未覆盖的最后 0.4 个 XML 四分音符外推成已知状态，不重写 `alignment.json` / `measure-map.json`。

## 5. 和声分析的特殊规则

1. **全体实际记谱最低音 `global_bass` 与归约层最低音 `layer_bass` 必须分开。** 某个上层三和弦在 E1 或 A3 持续层之上时，不可在同一标签里把“最低音是 E1”和“Gm7 的转位”混成一个无条件结论。
2. 根音与转位属于**所选和声结构**；转位只有在结构和低音属于同一分析层、音符依据相容时才有效。
3. 罗马数字基于指定调性/调式框架，显示“在 X 调性候选下”；它表示条件性读法，**不等于该和弦已被认定具有属/主等功能**。
4. 对带变音的和弦，不能静默省略关键变音并显示普通自然调内级数。必要时验证根据罗马数字重建的和弦音级与归约层实际音级是否一致；若不能一致就降为“条件性级数待审查”，保留原和弦名称与源音符。
5. 空心五度、分解音型、倚音、经过音、持续低音与多层音响，不得因不符合完整三/七和弦模板就强制填入某个 I/V；“实音集合”是合法事实，但应优先给出不越界的结构描述（如开放五度）。
6. **不要把当前音集滑动继承为背景和声。** 需要明确的时间范围和上下文证据才能发布持续性和声；第一轮仅完成几个有证据的示范区间，其余显示待分析。
7. 证据详情保留 `complete_vertical`、`bass_pitch_class_layer_reduction`、`instrument_family_layer` 的明确含义；层内读法不得冒充全体织体的唯一解释。源 note IDs、included/excluded 应可点开查验。
8. 记谱等音区别（如 E 与 F♭）在源记谱与调性判断中保留，不能因为 MIDI 音高相同就抹掉。

## 6. 配器分析的特殊规则

- **活跃乐器/分部 ≠ 配器分析结论。** 由 `completion.py` 的时值阈值推得的“持续层”“短音/运动层”属于规则提示；“旋律”“副旋律”“加倍”“配器交接”需要更明确的声部及上下文证据。
- 用 `part_id` / `instrument_ref` 的原始身份保证源可追溯，同时可在 UI 按木管、铜管、打击乐、键盘/拨弦、弦乐分组；`divisi` 不能被错误计作多种乐器。
- 活跃分部必须是**同一时间窗口中实际处于记谱时值的分部**，不能使用小节活动并集；无音头事件、隐藏音符与休止正确处理。
- “配器”详情应能回答：谁进入/退出；谁担任什么声部；谁加倍谁；音区和奏法如何变化；与前后段怎样交接。
- 在钢琴独奏时，乐器数为 1 并不意味着织体只有 1 层；应允许根据声部分化展示**同一乐器内部的旋律、低音、和声填充、装饰运动**。未核验则写候选，不凭乐器数直接下音乐学判断。
- 非定音打击乐进入活跃配器列表，但不进入定音和声音级集合。鼓槌/奏法对音色的解释也应区别于 XML 的直接事实。

## 7. 曲式与对位不要被此次整合降级

- 原有 Form、Counterpoint 仍然是一等公民，HUD 默认保持可见的简洁入口。
- 曲式分析继续支持 `Work → Movement → Section → Phrase → Motif`，保留相互重叠或竞争的曲式模型；MusicXML 小节标签不自动成为真实乐句边界。
- 对位展示具体声部、音程、节奏与模仿证据；当前只有音高/运动候选时必须区分“音程见证”与“严格对位认定”。
- 文献的宏观调性、曲式研究可挂到对应结构节点，不能不加验证就称为这一时刻唯一的和声功能。
- 诠释文章的选择、阅读位置、可跨多个非连续谱段的跳转逻辑保持不变。

## 8. 实施顺序（不要先无限扩大模型）

## 9. 必须通过的案例与回归测试

### 音乐及证据案例

1. **m.11**：若存在 Gm7 上层/E1 持续层等并列解读，展示归约层来源、全体低音、层内低音及罗马数字条件；不会把层内的转位与全体最低音误连。
2. **m.58（PDF第12页）**：当前音级仅见 G♭/D♭ 时，显示开放五度/实音集合；不得凭空补出三音并贴 I/V；背景和声无可靠证据时显示待分析。
3. **m.63 末弱起至 m.64**：展示 D/A 到 E 三和弦上层+A 持续/延后 D 低音的阶段差异；不把一小节全部瞬间混成一个和弦。
4. **m.520（PDF约95页）**：在小节内 `2` 处展示钢琴与低弦等进入，在 `11/4` 后正确加入低音单簧管；活跃分部在两时点必须不同。
5. **m.7**：E/F♭ 同音高、不同记谱拼写不被抹除；非定音打击乐只进入配器。
6. **m.34**：对应 PDF 物理第11页；独立点选阅读器只翻页，不 seek 音频。

### 系统行为

7. 四维 HUD 的组件测试：实时音集变化不重建曲式卡；仅乐器活动变化时不重建背景和声；证据链接准确关联事件 ID。
8. 实际播放/暂停、seek、变速、A/B循环、翻页、PDF高亮、视频切换继续工作。
9. 手动浏览 PDF 与正在播放的页分开；独立 XML 研究不跳录音。
10. 长诠释文章在播放、seek、证据开关切换后标题、选中项、**非零 `scrollTop`** 均不变；与技术详情面板互不干扰。

15. 桌面与窄屏实测：HUD 默认收起时以 PDF 为视觉主体；详情与文章各自独立滚动；无横向溢出、控件遮盖及无意义的大块重复留白。
