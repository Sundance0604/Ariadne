# 音乐分析与导聆撰写流程

目标是解释音乐材料怎样随时间发展。四个谱面技术维度提供不同证据，导聆再将它们组织为观众能听见的连续过程；不新增第五个动机面板，也不改变四宫格布局。

## 1. 先确定作品、版次和演出

从 `library.json`确定曲目与 `data_root`，读取 `project.json`、`metadata/recording.json`、alignment和PDF映射。区分作品谱面与演出时钟：拉威尔两场演出可以共享总谱研究，但艾马尔视频使用自己的录音投影，不套用齐默尔曼录音秒数。

记录PDF物理页、印刷小节号、XML小节ID、声部ID及源音符ID。MIDI参考段、识图计数候选和排练号不能互换。暂时没有可靠位置的材料保持未定位，不按文字长度或页数平均配时间。

## 2. 优先使用已有证据

| 证据 | 当前入口或位置 | 用法与边界 |
|---|---|---|
| 原谱和辅助材料 | `resource/` | 保留原文件；矢量谱、扫描谱、缩编与总谱分别判断 |
| 主要符号数据 | `analysis/musicxml/current.json` | 指向已保存的XML事件、时值、声部、和声、配器、声部关系及曲式证据 |
| 并列解释与时点激活 | `analysis/musicxml/interpretation-current.json` | 保留分析层及录音投影，区分局部音响与跨时背景 |
| 直接读谱窗口 | `analysis/score-studies/` | 对关键音高、节奏、移调、加倍及理论判断进行局部核查 |
| 研究事件与长文 | `analysis/structural-events.json`、`analysis/essays/` | 保留作者归属、谱面范围及实际阅读状态 |
| 拉威尔两模块研究 | `analysis/ravel-module-development.json` | 25条范围明确的组织性摘要，以及一组有源音符依据的局部对应 |

预计算播放只读取结果，不导入music21或mido。确实需要新解析时，另用可选分析环境和 `backend/musicxml_analysis/`入口生成新快照，不覆盖已激活数据。OMR和MIDI未匹配数清零不是开展独立音乐研究的前提。

## 3. 四维各自回答什么

| 模块 | 核心问题 | 不应自动推出的结论 |
|---|---|---|
| 和声 | 音响、低音、分析层与调性语境怎样改变？ | 分解音的集合不是同时和弦；局部音集识别不是功能和声或终止的最终认定 |
| 配器与织体 | 材料分配给哪些乐器，音区、音色与奏法怎样变化？ | 活跃分部数不是独立旋律数；最高音不自动是主旋律 |
| 声部关系与复调 | 主副旋律、支撑层、加倍、交接、模仿及线条之间怎样组织？ | 多件乐器或多个音头不自动构成复调；平行运动不自动是严格对位认定 |
| 曲式与主题发展 | 材料在哪里陈述、变形、模进或返回，承担什么结构功能？ | 相似音型不自动属于同一主题；速度、翻页或换配器不单独证明形式边界 |

拉威尔只扩展后两个模块的研究职责，和声、配器的既有分析逻辑保持独立。一个交接事件可以被共同引用：配器说明乐器与音色的转移，声部模块说明旋律身份和主副关系，曲式模块说明前后陈述及结构作用，避免三处重复同一句话。

## 4. 动机关系作为共享基础数据

先比较实际音符，再讨论主题身份。优先复用XML `form.json`中的 `motif_comparisons`、`materials`、`material_links`；旧 `backend/structure_analysis/motif.py` 的 `MotifAnalyzer`保留为辅助候选接口，不重建第二套主分析。

每组关系至少保留：

- 原型和对应片段的位置、声部及音符ID。
- 实音音程、记谱节奏或时值比例、移调距离及实际发生顺序。
- 比较方法的取音方式，如“上层五次攻击”，不能冒充已恢复的完整旋律。
- 支持对应的证据，以及分解公式、同时加倍、偶然相似等替代解释。
- 关系结论的范围、主题身份是否仍未认定、代理核查与人类／专家签核的区别。

现有拉威尔案例比较钢琴XML42–43小节与长笛XML67–68小节的五次攻击：音程与时值比例相同，相隔两个八度。当前只确认该局部对应，`theme_identity`保持`unassigned`。同时发生的同度或八度加倍不是多次独立主题陈述。

更新现有模块研究的专用入口：

```powershell
.\.venv\Scripts\python.exe scripts/build_ravel_module_development.py
```

它复用现有研究，并重新核对所引用的音符，不自动认证全曲主题网络。没有证据的模进、扩张、模仿或主题同一关系不强行补齐。

## 5. 文献怎样落到谱面

为每个文献观点记录作者、来源链接或书目信息、实际阅读页／节，以及它支持的具体音乐判断。区分全文、相关章节、摘要和仅出版信息，不能把摘要阅读提升为全文核验。

将文献编号与当前PDF物理页、XML小节和实际音符分别对照。若版次、编号、删节不同，保留映射依据或暂不绑定。文献中的主题名称、结构模型和历史解释应有归属，不变成无来源的系统定论。

“旋律下行”属于谱面观察；“这种转向削弱前文的上行预期”需要前后材料与语境支持；“讥讽战争”还需要独立的音乐学或历史依据。不能在这三层之间省略论证。

## 6. 从证据写成连续导聆

先建立一个片段的前后关系，再写当前段落。优先选择观众能跟着听见的变化，不机械填满栏目。

每段可以从以下问题中选择一两个重点：此刻听什么？它与此前有何联系？变了什么？这种变化起什么结构作用？哪些诠释有足够证据？不是每条字幕都回答全部问题。

推荐分层保存：

1. **谱面事实**：音符、节奏、声部、入口与实际范围。
2. **分析关系**：加倍或独立层、局部材料对应、乐句／段落功能。
3. **有来源的解释**：文献读法与可并列模型。
4. **给听众的短文案**：指出一个具体可听对象及其变化，完整解释留在网页证据中。

对视频分析的分布进行均衡时，先从实际显示规则计算所有文字区间的并集，再找音乐范围内的补集。原有退场、诠释互斥和淡出都应计入；不能只看JSON里的大段起止。以乐句、材料、配器、动态或织体变化给出补写候选入口，并保存正文有效范围；阅读长度决定停留，乐章停顿、末音与聆听间隔作为约束。覆盖率只帮助审查密度，不能由空白中点或等分时长反推音乐事件。普二十段试作采用人工写作与语义入口、程序安排阅读预算及审计的方法，保留既有文稿，见[实例](../../reports/prokofiev2-gap-fill-20261027.md)。

例如，把“持续层＋分解层：先辨织体，再谈对位”改为“持续层与流动层：大提琴以长音托住背景，低音提琴的六连音在其中流动”。前者是研究操作提示，后者指出观众可以听见的分工。

再如，把“高音短句与分解音型重新组合，并非新主题”改为“高音短句与分解音型重新组合，快段的展开换了一种面貌”。这样不把证据不足的主题身份判断写成否定结论。

## 7. 三种更新不要混淆

- **更新音乐研究**：修改或生成相应研究资料，保留来源、原稿及核验范围；不改录音时钟。
- **重新组织两类视频事件**：必要时使用 `scripts/video_export/sync_ravel_module_captions.py`；它会依据研究范围重建两类字幕安排，已有用户时间编辑应先备份核对。
- **只润色当前字幕**：使用编辑器修改当前JSON；不要重新生成整个事件表。既定规范化脚本 `scripts/video_export/polish_ravel_caption_text.py`保留当前编号、顺序、时间及可见性，但会采用其固定文案。

所有显示和生成入口读取同一个当前文稿。栏目名称、字号项与实际ASS标题一并同步；旧键只作读取兼容，不能让保存把新名称变回旧名。

## 8. 检查与发布

选择有真实谱面和录音映射的少量片段，检查原文是否能指导聆听、是否重复、是否有前后联系、是否越过证据范围。关系数据应能回到实际音符，而不是只证明JSON格式成立。

代码改动运行相关检查；同一结论通过后，不反复扩大无关测试。区分数据结构检查、实际HTTP加载、浏览器实播、人工试听和音乐内容审定，没有做的环节写清楚。

形成可读Markdown报告，说明现有事实、分析判断、来源、边界与未决问题。GitHub保存可分享的代码、研究及文档；用户演出视频、本地字幕草稿、缓存和未完成的大型OMR工程留在本机。视频制作的发布检查另见[视频流程](video-production.md)。
