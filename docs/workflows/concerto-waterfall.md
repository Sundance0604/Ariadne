# 协奏曲瀑布流：从总谱与录音到可复用的全曲视频

这份流程整理了普罗科菲耶夫第三钢琴协奏曲第一、第三乐章的实际制作方法。可执行脚本、两份终版对齐和视觉时间线在 [`tools/prokofiev3-waterfall/`](../../tools/prokofiev3-waterfall/)。渲染器在 [`tools/prokofiev2-waterfall/gpu-vfx-flow/`](../../tools/prokofiev2-waterfall/gpu-vfx-flow/)。这些对齐只绑定各自的谱面和录音；换版本必须重建，不要改曲名后沿用时间戳。

## 数据与可信度

1. 保存原始 MusicXML、原录音的 SHA-256、乐章／小节／声部表。先查 MusicXML 的重复音、跨小节连音、移调乐器、异常小节长度和不可能的钢琴和弦。第一乐章曾有不可弹的高音堆叠；第三乐章第 200–231 小节的钢琴小节比乐队小节异常地长。谱面是音高与声部候选，不是演奏时间的最终答案。
2. 用 chroma、音头特征和多分辨率 DTW 建立**全曲粗时钟**。它只限制逐音搜索范围，并帮助识别段落、停顿与 rubato；不能把它当成最后的音头、音尾。
3. 每个最终音符保留谱面 ID、乐器、音高、录音起止、音头与音尾证据来源。`score_clock_unmatched`、混音中的孤立峰、被其他声部遮盖的音都需要单独列出。未被确认的音不要伪装成已识别。

## 钢琴：分离、触键与音尾

钢琴必须先从协奏曲混音中分离，不能只在总录音里找峰。当前实现用 BS-Roformer-SW 在重叠的小段中提取钢琴，再以 Transkun 得到触键候选；在重叠**中点**切换片段，避免边界漏音。分离的 WAV 只用于该段分析，转写 MIDI 和按音高的频谱能量保存后立刻删除临时 WAV。

在正常谱段，按**同音高、先后顺序、一对一**把谱面事件配给转写触键。没有模型匹配时，只在分离钢琴的频谱能量出现明确增长时补音；混音峰只能作低可信候选。对低音和和弦，再检查能量由静到响的起点，修正转写模型可能稍晚给出的时间。第一乐章的 `align_full.py`、`extract_piano_sustain.py` 与 `piano_sustain.py` 实现了这套匹配和音尾约束。

第三乐章异常 XML 的第 200–231 小节说明：即使做了小节尺度归一化，左右手的相对记谱顺序仍可能错误。`performance_refinement.py` 在录音 302–389 秒以**分离钢琴的演奏触键为主轴**，再用附近谱面音高过滤，而不是把没有录音证据的谱面时钟音画出来。2:39 附近的低音八度则取分离钢琴能量真正开始上升的时刻。该段的 736 个原候选最终由 663 个与谱面音高核对过的演奏触键替代。这是该份谱与录音的局部修复，不能无审查地套在另一作品。

音尾同样要听录音：结合转写的释放、各音高的衰减和下一次同键触键；再限制同键重叠、单手超过五键、全钢琴超过十键等明显不合理的视觉状态。踏板和混响使“机械松键时刻”未必可从立体声录音精确恢复，因此保存 `release_source`，不要把约束估计称作真实键位传感数据。

## 管弦乐与弦乐：先判断谁在主奏，再判断何时进入

从 XML 的 `part_id`、乐器名、声部、力度、音区、织体密度和片段连续性建立候选主奏；再用录音的相应音高证据复核。主奏单线标为 `orchestra_melody`，主奏和弦标为 `orchestra_chord`，其余保留 `orchestra_support`。八度加倍要保留为同一旋律，其他同时出现的音可以是和声；不要因为全乐队一起变响就把所有弦乐都涂成主音。主奏弦乐与木管也应有触键亮光、粒子和光迹；伴奏要可见但更细、更淡。

强背景下，**最大音头峰常常是音已经响起以后的一次加重**。第三乐章 2:42–3:39 的拖后正由此产生。`performance_refinement.py` 改为检测谱面指定音高的首次显著频谱出现，比较前后能量，并由同时进入的不同乐器建立短语锚点；随后保持每个乐器自身的先后顺序。对已经响着的低八度音的高次谐波，不能误判成新的高音入口。证据不足时保留待审，不用固定整体提前量制造“先拖后赶”。此法在该段修正了 55 组主奏入口，仍须试听确认被遮盖的内声部。

第一乐章的 `classify_full_score.py` 和 `align_full.py` 同时考虑书面谱面、声道差异、音高特异的录音特征和短语连续性。被钢琴或齐奏遮盖的背景弦乐跟随已测得的局部乐队时钟，不强行吸附到无关的瞬态。主奏角色交接须逐段核对，尤其在快速跑动、同音反复和管弦齐奏处。

## 分段视觉、验证与局部重导

渲染时间线是**绝对时间**的：颜色、材质、背景图淡入淡出、粒子风场、光迹、音符和琴键亮光都由同一演奏时间决定。随机效果用稳定种子，因此同一时刻单独渲染或在全片渲染应相同。先静帧或短片验收，再做 4K／60 帧全片。已通过验收的键盘形状、音符形状和背景音层不能因改背景或对齐而意外改变。

每 20 秒一段导出视频，保留片段输入与渲染器的签名；只重画受影响窗口及粒子余迹可能跨入的下一窗口。沿用旧片的其余画面时，先验证切出的片段首帧与旧片对应帧一致，再合成一次原录音。最终检查时长、3840×2160、60 fps、立体声音轨、修改处帧可解码以及每个接缝的相邻帧差。进程退出、文件存在、时间线生成都不能单独证明视频已完成。

在清理前确认终版视频与最终对齐 JSON 都能读。仓库只提交代码、审校后的对齐与时间线、QA 和选定视觉素材；原录音、完整视频、模型权重、虚拟环境、临时 WAV、分段 MP4 和废弃样片留在本机或删除。重新处理新录音要更新指纹，并在独立目录生成新的证据缓存，禁止把旧缓存误用于新录音。

## 已知限制

- 立体声混音通常不能唯一确定每个弦乐声部的具体发音，也不能证明每个安静内声的真实音尾；保留审核标记并试听。上述数量是该演出的处理记录，不是通用准确率。
- 当前钢琴分离示例使用 Apple Silicon 的 MLX 命令行程序；Windows 可沿用谱面、匹配、QA、渲染接口，但须提供兼容的钢琴分离后端，不能假称这些示例无需调整就跨平台一键运行。
- 两部 4K 终版视频在本机，未纳入 Git；仓库中的最终 JSON 与选定素材用于复现。媒体文件需由持有者在本机按指纹提供。
