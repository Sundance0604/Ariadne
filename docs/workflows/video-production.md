# 视频生成与字幕制作流程

本文固化当前Ariadne已经使用的制作方式。所有命令从项目根目录执行；不需要重做网页布局或重新分析录音。

## 1. 先确认要修改的文件

唯一日常入口是根目录的 `编辑视频字幕.bat`，启动后选择普罗第二钢协完整版、鹅妈妈完整芭蕾、拉威尔左手钢协完整版或95秒样片。项目的资源包与字幕文稿成对保存在 `config/video-export.json` 的 `editor_projects` 中，默认选中 `editor_default_project`，不会把另一部作品的文稿写入当前项目：

| 内容 | 当前位置 |
|---|---|
| 普二完整版资源包 | `output/video-export/prokofiev2-full-001/` |
| 普二可编辑字幕 | `works/prokofiev-piano-concerto-2/video-export/captions-editable.json` |
| 鹅妈妈资源包 | `output/video-export/mother-goose-full-001/` |
| 鹅妈妈编辑文稿 | `works/ravel-mother-goose-video/video-export/captions-optimized.json` |
| 完整版资源包 | `output/video-export/ravel-full-001/` |
| 完整版编辑文稿 | `output/video-export/ravel-full-001/captions-editable.json` |
| 95秒样片编辑文稿 | `local/video-export/ravel-sample.json` |
| 字号偏好 | `local/video-export/font-sizes.json` |
| 最近成功视频的位置 | `local/video-export/latest-video.txt` |

不要从旧MP4反推当前字幕。用户编辑后的JSON是下一次制作的输入，旧 `edits-XXX/editing.json`只是那一次成片的快照。

普二当前有218条字幕、原PDF和双可视化。2026-10-27根据用户成片反馈收紧四栏，普通分析读完渐隐，乐谱纸张贴右；诠释改为宽幅缓升长文，显示期间暂时让出分析区与PDF，随后恢复当前谱页。之后为十段长空白增加18条（3长、15短），按已有谱面事件进入，保留阅读间隔及乐章停顿。只更新JSON、ASS与同步计划，用户自行生成和核查。详见[普二完整版指南](../guides/prokofiev2-full-video.md)。其他曲目未启用的新呈现规则保持原行为。

## 2. 只修改现有视频字幕

1. 双击 `编辑视频字幕.bat`，选择项目，核对窗口中的成片时长和文稿路径。
2. 选择字幕，修改正文、标题、起止秒数或可见性；字号在单独页签修改。
3. 外部文稿可点右上角“打开外部JSON…”，在文件窗口选择。支持含“字幕”数组的编辑稿，也支持含 `events`数组的 `annotations.json`。
4. 阅读、核实实际将显示的每条文字，然后点“保存并生成新视频”。等待进度到100%，使用“打开最新视频”观看。

“保存修改”只写文稿；“仅导出ASS”不编码视频。导入外部文件后，保存写入当前项目文稿，外部源文件不覆盖。重新载入磁盘上已更新的文稿前，不要用旧窗口覆盖它。

选择《鹅妈妈》完整芭蕾版会打开 `works/ravel-mother-goose-video/video-export/captions-optimized.json`。它与左手钢协完整版的文稿、输出包及偏好分别保存。旧完整版、鹅妈妈与字号专用批处理入口已移除，相关功能全部保留在同一编辑器中。

编辑器的“位置、字体与滚动”页签可按栏目修改横纵坐标、区域宽高、字体名称、字号和滚动倍速；“文字与出现时间”页签还可为每条字幕填写单独样式，留空沿用栏目设置。坐标以成片左上角为原点，单位为像素。滚动1为原速、1.5快一半、2为两倍，不改变字幕出现、结束时间或重复滚动。调快后滚动更早结束，末段停留供阅读。《鹅妈妈》当前默认1.5倍。字体须为本机可用字体；生成后的MP4不要求观看者安装字体。

这些设置写进可编辑JSON的“字幕样式”及各条“样式”，保存后须点“保存并生成新视频”。每次另存新成片，完整视频保留七个章节。

《鹅妈妈》当前把和声解读、配器说明与实时内容合在各自同一显示区：解读在前，当前音响／活跃乐器在后。原分段稿另存JSON的“分段和声配器底稿”，不作为第二组字幕输出。新增童话与论文转述的出处见同目录 `story-sources.json`；视频仍由用户自行生成和核查。

命令行等效入口：

```powershell
# 打开项目选择窗口
.\.venv\Scripts\python.exe scripts/video_export/edit_video_captions.py

# 直接打开鹅妈妈；拉威尔完整版使用 --project ravel-full
.\.venv\Scripts\python.exe scripts/video_export/edit_video_captions.py --project mother-goose

# 直接使用当前完整版JSON生成新MP4
.\.venv\Scripts\python.exe scripts/video_export/edit_video_captions.py --project ravel-full --render

# 仅生成ASS
.\.venv\Scripts\python.exe scripts/video_export/edit_video_captions.py --project ravel-full --ass-only
```

这条日常路径复用演奏视频、PDF缓存、原JS同步和已经保存的时间戳，不运行DTW、识谱、音乐分析、性能基准或完整测试套件。

`--full`保留为拉威尔完整版的兼容参数。命令行无项目参数的 `--render`／`--ass-only` 仍沿用旧样片行为；自动生成时应显式指定 `--project`。使用自定义 `--package` 时，默认文稿为该包的 `captions-editable.json`，也可用 `--document` 指定，避免误用其他项目文稿。

## 3. 字幕JSON约定

```json
{
  "字号": {
    "和弦": 36,
    "配器": 36,
    "声部关系与复调": 40,
    "曲式与主题发展": 40,
    "导聆": 40,
    "诠释": 50,
    "片头": 60
  },
  "字幕": [
    {
      "编号": "example-reading-1",
      "栏目": "声部关系与复调",
      "开始秒": 30,
      "结束秒": 40,
      "标题": "声部关系与复调",
      "文字": "持续音托住背景，快速音型在其中流动。",
      "显示": true
    }
  ]
}
```

上例仅说明格式，不是新增的已核验音乐事件。编号保持稳定，同一栏目内不要安排重叠时间。旧文件里的“对位”“曲式”仍可读取，当前拉威尔文稿使用新名称。

只润色文字时，保留编号、时间的数值及类型、数组顺序、可见性和字号。不要重新按页数均分时间，也不要用完整重建脚本覆盖用户已经修改的文稿。

## 4. 必须保持的画面规范

- 演奏MP4始终为全屏底层，保留原演奏音轨。
- 分析文字默认黄色楷体，无实体背景、边框、卡片或装饰；用户可在编辑器选择字体及位置。
- 和声在左上，配器在右上；左下三个槽位依次为声部关系与复调、曲式与主题发展、导聆。各槽位不随其他内容移动。
- 完整乐谱固定在右侧，配器不遮挡乐谱。高亮、播放线和翻页调用原播放器JS，不重新开发定位算法。
- 片头可以大幅居中、由下向上滚动。拉威尔音乐入口为原视频27.5秒；按实际帧，片头最迟24.48秒清空，随后至少三秒只保留演出画面。
- 演奏中诠释固定在底部中部，必要时由下向上滚动。诠释显示期间乐谱隐藏，内部时间继续更新，结束后恢复原尺寸和正确位置。
- 短文案不必滚动。相同文字只显示一次，滚动结束后不重新起滚；阅读结束与下一条之间应留出安静区间。已有时间由用户确认后保留。

## 5. 发布文案检查

研究界面可以说明证据状态，正式视频不能显示“待分析、待复核、候选、TODO、调试”等内部工作提示。

不能只删除限定词后保留未确认的结论。应整条隐藏，或用有依据的完整表述替换。例如，尚不能确认和弦类别时，可以使用现有XML音符支持的“片段音集”和“低音”，不能直接宣布某个和声功能。跨时段音集不得写成同一瞬间的和弦。

同样，“不能仅凭换配器认定新主题”不能润色成“这不是新主题”。改写应保持原结论的证据范围，不增加作曲家意图、演奏心理或历史情节。

现有专项工具：

```powershell
# 对当前完整版进行既定文案规范化，保留时间与编号，先备份
.\.venv\Scripts\python.exe scripts/video_export/polish_ravel_caption_text.py
```

该脚本包含拉威尔已整理的固定文案，不能用来无条件替代其他作品的分析。它会重写相应文案；自由编辑后的新版本应优先在编辑器内逐条处理。

## 6. 首次建立新的资源包

先准备同一演出的媒体、已有alignment、原PDF及审核后的事件。可选导出依赖为：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-export.txt
```

还需Node.js执行原生JS模块、支持libass和libx264的FFmpeg。普通播放不依赖这些处理组件。通用包准备、乐谱缓存、合成及验证入口见[视频CLI指南](../guides/video-export-cli.md)。

`scripts/video_export/build_ravel_full_video.py`是当前拉威尔素材的专用扩展器，依赖先前样片包。它从原演出0—1197.85秒建立整曲包，保留结尾画面，不能只换曲名就套用于其他作品。它默认创建新目录；日常改字不要运行它。

## 7. 时间、输出与必要检查

`outputTime`是成片秒数，`videoTime`是原视频秒数，`musicTime`是减去正式音乐入口后的秒数。当前连续全片从原视频0秒开始，前两者相同；以后剪辑时仍须显式映射。

依据源视频实际帧时间戳合成，不假设所有素材为25FPS。原AAC音轨复制，原MP4不修改。每次输出新 `edits-XXX/`目录，里面保留该轮字幕、配置、文稿快照、乐谱计划、日志和新MP4。

小范围检查应直接针对这次文稿和成片：名称、实际字幕、片头三秒清空、诠释与乐谱互斥、换页、音画位置及普通播放器观看。修改文字无需重跑与该修改无关的识谱、指纹对照和大规模基准测试；未做试听或浏览器实播时，报告中如实区分。

## 8. 保存与GitHub

保留可编辑JSON、ASS、PDF缓存、alignment、annotations、配置和审核报告。最新字幕更改后，旧MP4仍是旧版本，必须另存新成片。

`output/video-export/`、`local/`、演出视频和工具缓存只留本机。GitHub保存代码、可共享配置、流程文档、研究数据及必要证据；不上传演出录像。推送不是删除本机材料的理由。
